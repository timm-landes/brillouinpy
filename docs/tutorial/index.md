# Tutorial

This tutorial builds up a complete Brillouin imaging analysis workflow, one stage
at a time:

**load → remove the IRF → preprocess → explore → fit → export**

Each stage has its own page (in the sidebar, and linked below). The pages follow
the runnable scripts in the [`examples/`](https://github.com/timm-landes/brillouinpy/tree/main/examples)
folder of the repository, in order, and each script is self-contained
(`python 01_load_data.py`, etc., from inside `examples/`).

Two ordering choices are worth calling out up front:

- **IRF removal happens right after loading**, before the rest of preprocessing,
  since normalisation/denoising would otherwise be skewed by the IRF's much
  larger intensity.
- **Explore before you fit.** Starting with the mean/variance spectra and, from
  there, unmixing/decomposition/clustering tells you how many Brillouin modes
  (`expected_peaks`) are actually present and gives you a rough `p0` to start the
  fit from, rather than guessing both blind.
- **[Fitting](fitting.md)** covers the single fixed-mode-count case (`DHO` /
  `Lorentzian`, the parameter conventions, choosing the lineshape).
  **[Multi-component](multi-component.md)** picks up where that leaves off: images
  where the number of modes is unknown or varies pixel to pixel
  (`estimate_peak_count`, `expected_peaks='auto'`, `segmented_fit`), and how those
  compare to the model-free methods.

If no real measurement data is found at the `project_path` set near the top of a
script, it falls back to a small synthetic dataset generated by
`examples/_synthetic_data.py` - so every example produces a sensible result
without access to real data, and every figure in this tutorial was rendered
straight from that synthetic data (see `docs/generate_tutorial_images.py`) - the
one exception being the real-measurement panel on
[Removing the instrument response](irf-fit-comparison.md), which needs a real
dataset and is included for illustration. Where
a script needs output from an earlier one (e.g. the fit result for the export
page), it looks for a `pp_data/` folder and falls back to synthetic data again if
it isn't there, so the scripts can be run in any order.

```{admonition} A note on the synthetic data
:class: tip

The synthetic spectra used throughout this tutorial are built from the same Damped
Harmonic Oscillator (DHO) lineshape the package fits with (see
[Fitting spectra](fitting.md)). Because the DHO lineshape is symmetric in
frequency, a single simulated "Brillouin mode" at a frequency shift of e.g.
8.5 GHz always shows up as **two** peaks, at +8.5 GHz and -8.5 GHz - exactly like
the real Stokes and anti-Stokes peaks in a measured Brillouin spectrum. That's
why every spectrum plot shows a symmetric doublet rather than a single peak, and
why `expected_peaks=1` in the fitting step (which counts *modes*, not individual
peaks) is still the right setting for it.
```

## Where to go from here

- The full [API Reference](../api/index.rst) documents every class and function
  used here, including parameters not shown in these excerpts.
- All ten scripts live in `examples/`, ready to copy and adapt to your own data -
  just point `project_path` (and the `mirror_spacing`/`scan_amplitude`
  interferometer parameters in `utils.brillouin_spectral_axis`) at your
  measurement.
- The figures were generated by `docs/generate_tutorial_images.py`; if you change
  the underlying examples in a way that would make them misleading, re-run that
  script (`python docs/generate_tutorial_images.py` from the repository root).
